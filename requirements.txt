# Neoantigen MHC-I binding prediction. The patent pipeline's MHCLoader
# (engine/py/immune/mhc_loading.py) and the MAD pipeline's
# NeoantigenPredictor (cognisom/genomics/neoantigen_predictor.py) both
# prefer MHCflurry when available and fall back to a position-weight
# matrix scorer when not. Pinning the version here eliminates the drift
# risk flagged in docs/patent/MAD_INTEGRATION_AUDIT.md (two parallel
# installations loading different model versions).
#
# Production note: MHCflurry is now installed in the production image, and
# Dockerfile.prod runs ``mhcflurry-downloads fetch`` to bake the model weights
# in (~600 MB). Before this, prod silently ran the PWM fallback, whose scoring
# is quantised to a handful of IC50 values and whose best achievable score
# (52.8 nM) sits above the 50 nM "strong binder" threshold -- so
# strong_binder_count was structurally always zero.
#
# Requires Python <= 3.12: mhcflurry 2.0.6 imports the stdlib `pipes` module,
# which was removed in 3.13. CI and the production image are both 3.11.
mhcflurry==2.0.6
# MHCflurry's class1 predictors run on TensorFlow and it is NOT pulled in by
# `pip install mhcflurry`. Without it the package imports and its weights
# download, but Class1PresentationPredictor.load() dies inside
# configure_tensorflow() with ModuleNotFoundError -- i.e. it looks installed
# and silently is not usable. tensorflow-cpu, not tensorflow: the production
# image is CPU-only by design and the CUDA wheels add gigabytes.
#
# Upper bound is <2.16, not <2.17: TensorFlow 2.16 switched the bundled Keras
# to 3.x, which dropped the TF1-compat shim mhcflurry 2.0.6 calls --
# tensorflow.compat.v1.keras.backend.set_session -- giving
# "module 'keras._tf_keras.keras.backend' has no attribute 'set_session'".
# 2.15 is the last release that ships Keras 2 by default.
tensorflow-cpu>=2.13,<2.16
